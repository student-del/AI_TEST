# AI Agent 文档检索受阻的常见原因

AI Agent 检索在线文档时出现“被防火墙拦住”，通常不是某一种单一故障，而是多层访问控制的统称。

## 主要原因

1. **Agent 运行环境的出站网络限制**
   沙箱可能默认关闭或限制公网访问，以降低数据泄露、恶意下载和供应链攻击风险。此时，请求甚至还没有到达目标网站。

2. **目标网站的 WAF 或反机器人策略**
   网站可能根据 IP、请求频率、User-Agent、Cookie、JavaScript 挑战、CAPTCHA 或浏览器指纹判断流量。自动检索工具不像完整浏览器，容易收到 403、429 或挑战页面。

3. **企业代理、地域或 DNS 限制**
   请求可能经过组织代理、防火墙、内容过滤器或受限 DNS；目标域名、文件类型或下载地址可能被策略阻止。

4. **身份与权限不足**
   文档需要登录、组织成员资格、订阅权限、VPN 或有效会话。表面上像“拦截”，本质上可能是 401/403 权限问题。

5. **工具能力边界**
   普通 HTTP 抓取工具通常不能完成复杂登录、JavaScript 渲染、弹窗确认或验证码；浏览器自动化更接近真实用户，但也受沙箱权限和站点政策约束。

6. **站点自身故障或限流**
   429、5xx、连接超时、CDN 异常不一定是防火墙。高频并发检索也会触发临时限流。

## 如何区分

- DNS 解析失败、网络策略错误：更像本地沙箱或网络出口限制。
- 401：通常缺少身份认证。
- 403：可能是权限、WAF、地域或机器人策略。
- 429：通常是频率或配额限制。
- 返回 CAPTCHA／JavaScript challenge：通常是反自动化系统。
- 浏览器能打开、抓取工具不能：多半与登录会话、JavaScript、Cookie 或浏览器指纹有关。

因此，Agent 所说的“被防火墙拦住”有时是便于理解的概括。更准确的做法是报告具体错误码、失败发生在哪一层，以及是否可以改用官方 API、已授权浏览器会话、本地文档或用户提供的内容。

## 2026-07-14：OpenAI 官方文档实测

在当前 Codex 会话中对 `developers.openai.com` 做了分通道测试：

- 内置 Web 检索可以搜索并打开普通官方文档，例如 `/api/docs/guides/text`，页面内容可正常读取。
- Web 通道直接打开 `/codex/codex-manual.md` 返回内部错误，未取得正文。
- Codex 手册下载助手对该 Markdown 地址执行 `HEAD` 时收到 HTTP 403。后续用同一助手访问普通 HTML 文档也得到 403，因此它不是该 Markdown 资源独有的问题，更可能来自该命令所使用的受控网络出口、代理或上游 HTTP 策略。
- 工作区本机的 PowerShell `Invoke-WebRequest` 和 `curl.exe` 对同一域名均无法建立连接；curl 返回错误 7、HTTP 状态 `000`。这是本机 shell 出站网络层的限制，不是目标页面返回的 HTTP 拒绝。
- 当前会话未暴露 OpenAI Developer Docs MCP 工具；尝试用 `codex mcp add` 安装时发现 shell 中没有 `codex` 可执行命令，因此无法在本轮补建 MCP 通道。

结论：OpenAI 官方文档并未被整体拦截。当前至少存在三条不同访问路径：内置 Web 通道可用；普通 shell 直连被出站网络边界阻断；已批准的手册助手能使用另一条受控出口，但该出口上的请求统一得到 403。将所有失败统一称作“防火墙拦截”并不准确。

### 进一步定位与解决方向

- 普通 shell 中，Node `fetch` 返回 `EACCES`，curl 返回错误 7/HTTP 000；这与工作区采用 `workspace-write` 沙箱且网络受限相符。解决方式是针对必要且范围明确的命令申请网络升级权限，而不是全局放开 shell。
- 手册助手属于当前环境已批准的命令前缀，所以它与普通 shell 使用不同的权限路径。它对手册 Markdown 和普通 HTML 页面都返回 403，说明问题不是文件类型或单个 URL。
- 助手实现会先尝试 Node `fetch`、失败后再尝试 curl，并只保留最后一次错误。因此最终显示的 403 不能单独证明是 OpenAI 源站 WAF；它也可能由受控出口代理返回。要最终区分，需要保存响应头/响应体，检查 `Server`、`Via`、`CF-Ray` 或代理自定义头。
- 最稳妥的文档访问路径是安装并启用官方 OpenAI Developer Docs MCP，然后重启 Codex；当前 shell 没有 `codex` 可执行文件，所以需在真正安装了 Codex CLI 的宿主终端执行配置，或由管理员/产品环境提供该 MCP。

### 沙箱外验证结果

经用户批准，在沙箱外分别执行 `HEAD` 和 `GET` 请求，普通 OpenAI HTML 文档均返回 403，关键响应头如下：

- `Server: Vercel`
- `X-Vercel-Mitigated: deny`
- `X-Vercel-Id: hnd1::...`

这将 403 明确定位到 OpenAI 文档站点前的 Vercel 防护层，而不是 Codex 本地助手自己生成的状态码，也不是只禁止 `HEAD`。较可能的触发条件是当前公网出口 IP 的信誉、机房/代理出口分类、地域节点策略或自动化客户端特征；仅凭响应头无法确定是哪一条具体规则。
