# CLAUDE.md 与 auto memory 的区别辨析

> 讨论问题：项目里的 `CLAUDE.md` 和项目级的 auto memory（`MEMORY.md` + 分类记忆，含 `project` 类型）本质上是否一样？
>
> 结论：**不一样，但互补。** 二者唯一的共同点是"项目范围内、跨会话持久、影响 Claude 行为"；除此之外几乎所有属性都相反。它们对应业界通用的"静态指令层 + 动态记忆层"双层结构。
>
> 更新时间：2026-07-11

---

## 一、术语澄清

| 名称 | 指代 | 本项目中的位置 |
|------|------|----------------|
| CLAUDE.md | 项目指令文件（入库、进系统提示） | `E:\AI_TEST\CLAUDE.md` |
| auto memory | 跨会话文件记忆系统（索引 + 分类记忆文件） | `C:\Users\juwei\.claude\projects\E--AI-TEST\memory\` |
| project 类记忆 | auto memory 里专记"项目动态"的一种类型 | `memory/` 目录下的某个 `.md` |

用户问的"项目级 memory"即 auto memory（其中 `project` 类型是它的一个子集）。

## 二、本质区别对照

| 维度 | CLAUDE.md | auto memory |
|------|-----------|-------------|
| 存放位置 | 仓库内，随代码走 | 仓库外（`~/.claude/projects/...`） |
| 版本控制 | 入 git | 不入 git |
| 谁维护 | 人手写、审阅、提交 | Claude 自主观察写入 |
| 共享范围 | 团队共享 | 个人私有、单机本地 |
| 加载方式 | 全量进系统提示（eager） | 仅 `MEMORY.md` 索引常驻，正文按需读取（lazy） |
| 内容性质 | 规范/指令（约定、必须遵守的规则） | 观察/事实（画像、偏好、项目动态、外部指针） |
| 权威性 | 高——OVERRIDE 默认行为，MUST follow | 上下文性——"某时刻为真"，用前需校验、可能过时 |
| 变更方式 | 人工编辑 + commit | Claude 边工作边自主增删 |
| 变更节奏 | 慢、稳定 | 快、随学随改 |
| 信任等级 | 无条件执行 | 先验证再用，冲突时信当下 |

## 三、一句话概括

- **CLAUDE.md = 项目宪法**：人立的、明文的、团队共享的、必须执行的规则。
- **auto memory = Claude 的私人工作笔记**：它自己记的、私有的、需要复核的观察。

## 四、业界对应（承接《历史信息重要性分级与动态调整机制.md》）

二者恰好对应 OpenAI Codex 的双层设计，是行业通用范式：

| 本项目 | Codex 对应 | 层性质 |
|--------|-----------|--------|
| CLAUDE.md | `AGENTS.md` | 静态指令层：人写、入库、第一天就定的约定 |
| auto memory | `~/.codex/memories/` | 动态记忆层：自动生成、跨会话涌现、单机私有、会老化遗忘 |

## 五、内容会重叠，但归属清晰

同一条信息（如"用户喜欢简洁回复"）既可写进 `feedback` 记忆（Claude 观察、私有），也可写进 CLAUDE.md（人规定、共享）。放哪取决于其**性质**：

> - 稳定的、团队都该遵守的、要强制执行的 → **CLAUDE.md**
> - 个人的、涌现的、试探性的、可能过时的观察 → **memory**

即使内容相同，Claude 对待方式也不同：CLAUDE.md 无条件执行；memory 需先回读当前代码/事实校验，冲突时以当下为准。

## 六、核心结论

CLAUDE.md 与 auto memory **不是同一事物的两种叫法**，而是一对分工明确的互补层：一个是"人 → Agent"的权威规则下发通道（声明式、共享、稳定），一个是"Agent 自我积累"的观察记忆通道（描述式、私有、动态、需校验）。理解这条分界，才能正确决定"某条信息该写进哪里"。
