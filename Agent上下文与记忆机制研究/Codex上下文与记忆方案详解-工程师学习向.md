# OpenAI Codex 上下文与记忆方案详解(工程师学习向)

> 面向想学习 Agent 上下文工程的工程师。Codex 的方案哲学是**"简单但有原则"**——正因为取舍清晰、可解释,它是研究 Agent 记忆/上下文设计的极佳范本。本文详解其**三层静态优先级 + 记忆老化遗忘**的完整架构,逐层讲"怎么做、为什么、解决了什么、有何优势、还能怎么改"。
>
> 承接《历史信息重要性分级与动态调整机制.md》4.2 节。
> 更新时间:2026-07-12

---

## 全景:三层解耦的上下文系统

Codex 把"历史信息治理"拆成三个**彼此解耦、职责单一**的层。这本身就是第一个值得学的设计——不同性质的信息用不同机制管,不混为一谈。

```
┌───────────────────────────────────────────────────────────┐
│ Layer 1  AGENTS.md —— 静态指令层(人写、入库、就近优先)      │
│   稳定约定,永远在场,发现即拼接                              │
├───────────────────────────────────────────────────────────┤
│ Layer 2  Memories —— 动态记忆层(自动生成、双模型、会老化)    │
│   跨会话涌现的事实,异步抽取 + 巩固,30 天遗忘                 │
├───────────────────────────────────────────────────────────┤
│ Layer 3  Compaction —— 会话内窗口管理(交接式摘要)           │
│   单会话超窗时压缩,用户消息特权保留                          │
└───────────────────────────────────────────────────────────┘
```

| 层 | 时间尺度 | 谁写 | 是否入库 | 核心机制 |
|----|---------|------|---------|---------|
| AGENTS.md | 永久 | 人 | 是 | 层级发现 + 拼接 |
| Memories | 跨会话 | Codex(异步) | 否(本地) | 双模型流水线 + 老化 |
| Compaction | 单会话 | Codex(实时) | 否 | 交接式 LLM 摘要 |

---

## 一、Layer 1:AGENTS.md —— 就近优先的静态指令

### 怎么做

- **层级发现(hierarchical discovery)**:从 `~/.codex/AGENTS.md`(全局)出发,沿 git 根目录一路走到当前工作目录,把沿途每一层的 `AGENTS.md` **逐级拼接**。
- **就近覆盖**:任意层可放 `AGENTS.override.md`,就近覆盖同级的 `AGENTS.md`。
- **32 KiB 硬上限**:超出静默截断。
- **兼容回退**:`project_doc_fallback_filenames` 可让 Codex 读 `CLAUDE.md`、`.cursorrules` 等其他格式。

### 为什么这么设计(教学点)

- **就近优先 = 具体优先**:越靠近当前代码的目录,其约定越具体、越该压过全局的泛泛之规。层级拼接天然实现了"通用规则打底、局部规则细化"。
- **32 KiB 上限是一种强制纪律**:逼你把最重要的约束写在前面,而不是堆砌成一本没人读的手册。

### 解决了什么问题

跨会话的稳定约定(用哪个包管理器、测试怎么跑、项目特有脚本)**不必每次重讲**;且因为入库,**全团队共享同一套规则**。

### 优势

确定性强(纯文本拼接,零推理)、可版本控制、可 review、可跨工具复用。

## 二、Layer 2:Memories —— 最值得学的双模型流水线

这是 Codex 方案里最精巧的部分:一条**异步的、两阶段分离的**记忆生成流水线,外加一套**老化遗忘**机制。

### 阶段 1:抽取(extract_model)—— 按会话、异步、只进暂存区

```
触发:某会话空闲约 6 小时后(不打断任何活跃会话)
  ↓
一个轻量 agent 采样该会话对话
  ↓
按严格 JSON schema 抽取"值得记的"
  ↓
密钥脱敏(secret redaction)
  ↓
写入本地 SQLite 的 stage1_outputs 表
   (raw_memory / rollout_summary / rollout_slug)
  ↓
【注意】此时还没写进 ~/.codex/memories/ 目录
```

### 阶段 2:巩固(consolidation_model)—— 全局锁、git diff、子 agent 合并

```
获取全局锁(防止并行写冲突)
  ↓
载入近期阶段1产物(默认 ≤256 个 rollout,硬顶 4096)
  ↓
同步到磁盘工作区 → 对上一版 baseline 做 git diff
  ↓
派生一个 consolidation 子 agent:合并 / 打补丁 / 丢弃候选
  ↓
写出最终 markdown 到 ~/.codex/memories/
```

### 存储与召回

- **存储**(纯 markdown):`memory_summary.md`(薄索引)、`MEMORY.md`(手册)、`raw_memories.md`、`skills/`、`rollout_summaries/`。
- **召回**(非向量):会话启动读 `memory_summary.md` 全文,截断到 **~2,500 token**;需要更深就让 agent 对 `MEMORY.md` 做 **grep**(纯子串关键词匹配,无 embedding)。

### 老化遗忘(核心亮点)

| 配置 | 默认 | 行为 |
|------|------|------|
| `max_rollout_age_days` | 30 | 超过 30 天的会话不再参与记忆生成 |
| `max_unused_days` | 30 | 30 天未被召回的记忆,下次巩固时被剔除 |

外加**引用反馈回路**:agent 在回答里引用了某条记忆 → 更新 `stage1_outputs` 的使用计数与最后使用时间 → 影响未来优先级。**用得越多越保鲜,用不到就淘汰**——这正是《重要性分级》报告里"访问即强化 + 久未用即遗忘"的工程落地。

### 为什么这么设计(教学点)

1. **异步(6hr idle)**:记忆生成是重活(要跑模型),放到会话空闲后台做,**绝不拖慢主循环**。
2. **两阶段分离**:抽取(per-session,轻)与巩固(跨 session 合并,重且要加锁)职责不同、频率不同,拆开才能各自优化。
3. **git diff 做增量**:把"记忆库"当成一个可 diff 的工作区,巩固只处理增量,避免全量重算。
4. **grep 而非向量**:牺牲语义召回,换来零索引维护、零 embedding 成本、结果可解释、跨机器无状态。对"数量有限的项目级事实"这是合理取舍。
5. **本地 + 脱敏**:记忆留在本机、密钥先擦除——隐私与安全优先。

## 三、Layer 3:Compaction —— "交接而非誊写"

### 怎么做

- **触发**:上下文约 95% 时。
- **用户消息逐字保留**:最近约 **20K token** 的用户消息原样不动。
- **助手回复 + 工具结果**:**物理删除**,由一段 handoff 摘要替代。
- **重建后的上下文只三部分**:保留的用户消息 + 交接摘要 + 刷新的初始上下文。

### 核心哲学(一句话记住)

> **"用户说的最准,模型说的可重写。"**(What the user said is most accurate; what the model said can be rewritten.)

摘要被当成一段"给下一个模型的工作交接",前面加 `SUMMARY_PREFIX`:
> "另一个语言模型开始解决这个问题并产出了它思考过程的摘要……在已有工作上继续,避免重复劳动。"

### 双路径

- **本地路径**(非 OpenAI 模型):完全开源可见(`codex-rs/core/src/compact.rs`),摘要作为 user 消息发送。
- **远程路径**(OpenAI 模型):调 `POST /responses/compact`,返回加密 blob。(注入实验证明服务端提示词与开源本地版几乎一致。)

### 其他工程细节

- 压缩后**总是重新注入新鲜的初始上下文**,剥离陈旧的 system/developer 消息。
- **模型切换感知**:切到更小窗口的模型前,先用旧模型压缩。
- **Compactor 2 重写**修复了早期"摘要的摘要"逐次退化(drift)的问题。

## 四、Codex 方案解决了什么问题(教学总结)

| 问题 | Codex 的解法 | 在哪一层 |
|------|-------------|---------|
| 跨会话稳定约定要反复重讲 | AGENTS.md 入库 + 就近拼接 | L1 |
| 通用/局部规则冲突 | 层级发现,就近覆盖 | L1 |
| 手册膨胀没人读 | 32 KiB 硬上限逼你精简 | L1 |
| 记忆生成拖慢交互 | 6hr idle 异步后台生成 | L2 |
| 抽取与合并耦合、并发写冲突 | 两阶段分离 + 全局锁 | L2 |
| 记忆无限膨胀 | 30 天老化 + 引用反馈淘汰 | L2 |
| 密钥泄漏进记忆 | 抽取时脱敏 | L2 |
| 单会话超窗 | 交接式 LLM 摘要 | L3 |
| 压缩丢失用户意图 | 用户消息 20K 逐字特权保留 | L3 |
| 切模型后窗口不够 | 模型切换前先压缩 | L3 |
| 摘要逐次退化 | Compactor 2 重写 | L3 |

## 五、核心优势

1. **哲学一致、可解释**:每一层职责单一,取舍写在明处("用户说的最准")。对学习者极友好——你能说清它为什么这么做。
2. **用户意图保真**:压缩时用户消息逐字保留,是所有主流 agent 里对"用户原话"保护最直接的。
3. **不打断主循环**:记忆生成全异步,交互零延迟代价。
4. **防膨胀**:老化 + 引用反馈让记忆库自我瘦身,不会越用越臃肿。
5. **隐私与安全**:本地存储 + 密钥脱敏 + 读写双开关。
6. **可移植的记忆库**:纯 markdown + grep,无向量索引,跨机器/可 diff/可手查。

## 六、改进点与局限(诚实分析)

### 1. AGENTS.md 可能"帮倒忙"(ETH Zurich / LogicStar.ai 2026 实证)

一项 2026 研究给出反直觉结论:

| 指标 | LLM 生成的 AGENTS.md | 开发者手写的 |
|------|---------------------|-------------|
| 成功率 | **-3%** | **+4%** |
| 推理成本 | **+20%** | **+19%** |

原因:
- **过度遵从(over-compliance)**:文件里提一句 `uv`,它的使用就从近乎零飙到每任务 1.6 次。
- **推理 token 膨胀**:有上下文文件时 GPT-5.2 多用 **22%** 推理 token——它把每条说明都当成必须满足的约束。
- **冗余**:LLM 生成的文件大多在复述 repo 里已有的内容;把文档移走后这些文件反而变得有用(+2.7%)。
- **位置偏置**:AGENTS.md 处在 developer 消息层、位于用户提示之上、永远在场,会**污染一切**——你提什么它就更倾向用什么,哪怕不相关。

> **实践建议**:从**空文件**开始,只在 agent **反复**做错某事时才加一条。写"包管理器、测试命令、项目脚本、只存在于开发者脑子里的约定";别写"代码库概览、目录结构、框架介绍"(这些 agent 自己能读)。**Less is more。**

### 2. Compaction 物理删除助手推理与工具结果

用户消息保住了,但**助手的推理过程和工具结果被物理删除**、不可逆。中间态(为什么这么改、试过哪些死路)只能靠摘要转述,细节会丢。

### 3. 无多级压缩:从"不压"直接跳到"全量 LLM 摘要"

Codex 在 95% 处一步到位做全量摘要,**没有 Claude Code 那样的 5 阶段梯度**(磁盘持久化 / 剪裁 / 微压缩 / 折叠 / 全量)。简单,但也少了"廉价可逆手段先上"的缓冲。

### 4. 远程路径加密不可审查

OpenAI 模型走 `/responses/compact`,摘要是加密 blob,客户端**看不到也改不了**——可控性与可调试性下降。

### 5. grep 召回的语义盲区

关键词子串匹配,**没有语义检索**。同义不同词(如记忆写"鉴权"、查询用"登录认证")可能召回不到。项目事实少时够用,规模一大就露短。

### 6. 记忆机制的地域限制

Memories 在 **EEA / 英国 / 瑞士** 发布时不可用。

### 7. 通用陷阱:滑动窗口摧毁 prompt cache

若"stub 替换"每步用滑动窗口重算,窗口一移就使**整个前缀缓存失效**。一条真实 177 步会话的 trace:从第 7 步起 **83% 的成本($77.30 中的 $64.80)花在缓存重写上**。**修法:stub/摘要决策必须单调**——一旦标记为 stub 就永远是 stub。(Codex/Claude 都遵循此原则,是自建系统必须警惕的坑。)

## 七、给工程师的可迁移takeaways

如果你要自建 Agent 记忆/上下文系统,从 Codex 能学到 7 条:

1. **三层解耦**:静态指令 / 动态记忆 / 会话压缩,分开治理,别混。
2. **记忆生成异步化**:放到空闲后台,绝不阻塞主循环。
3. **抽取与巩固分离**:轻的按会话跑,重的跨会话加锁合并。
4. **老化 + 引用反馈**:给记忆加"最后使用时间/引用计数",自动淘汰,防膨胀。
5. **压缩特权保护用户消息**:用户原话逐字留,模型输出可重写。
6. **stub/摘要决策单调**:保护 prompt cache,别让滑动窗口毁掉前缀缓存。
7. **指令文件 less is more**:从空开始,按实证增补,警惕过度遵从与位置偏置。

> 一句话总评:**Codex 的上下文方案不是最复杂的,却可能是最"讲得清"的**——它用清晰的分层和明确的哲学,把"该保什么、该忘什么、该压什么"回答得干净利落。对学习者而言,理解它的取舍比记住它的参数更有价值。
